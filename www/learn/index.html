How it works

Four parties: you, in your browser; the recipient, in theirs; the server, which stores ciphertext; and this site, which serves pages and code and receives nothing. Here is what each holds at every step.

Sending a file as a transfer

StepWhere it happensYou holdThe server holds
1. You drop a fileyour browserthe filenothing
2. The name is wrapped in front of the file in an envelopeyour browserfile and name, as one buffernothing
3. A fresh AES-256-GCM key is made and the buffer is encryptedyour browserthe key, the ciphertextnothing
4. The ciphertext is uploaded: create, upload, completeyour browser to the serverthe keythe ciphertext, its size, the time, a hashed IP, a content type hint
5. The link is built with the key after #, and drawn as a QR codeyour browserthe linknothing: browsers never send the fragment
6. You hand the link over, by any channelyou to the recipientthe link, in your keysthe ciphertext
7. The recipient opens it: download, decrypt, unwraptheir browserthe ciphertext, and a download count

The server could not read the file at any step, and never learned its name. Security: what the server sees is the full list.

Sending into a vault instead

Steps 1 to 3 are the same, per file. Instead of one transfer, the files are committed into a vault: each file becomes an encrypted object, the folder listing is itself encrypted entry by entry, a commit points at the tree, and the whole thing is published with a compare-and-swap so that two devices never overwrite each other. The link carries the read key, derived one way from the vault key: it opens every file and every version, and can change nothing. The vault key stays in your keys. Vaults and keys has the rest.

QR codes and friendly tokens explains the trade each makes.

What runs where

The pages are this site's. The code they run is api.send.sgit.ai v0.1.1, pinned by address, with a manifest of every file's hash copied into this repository and checked by the gate. The server is whichever SG/Send host you choose in Settings: the hosted one at send.sgraph.ai, your own, or one in memory on your laptop.
